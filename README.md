# SPECTRE.OS

> **TERMINAL FOR IDEAS**

## Introduction

Hi, I'm **Spectre**.

I built **SPECTRE.OS** as a different way of presenting myself and the things I create.

Instead of building a traditional developer portfolio with a landing page, an about section, and a collection of project cards, I wanted to turn the entire portfolio into an interactive operating-system-style environment.

SPECTRE.OS is the result of that idea.

I designed the interface, interactions, visual identity, terminal experience, project system, and overall user experience around the concept of a personal operating system. The goal wasn't simply to make a website that *looks* like an OS, but to make the portfolio itself feel like something you can explore and interact with.

The project also serves as a space where I experiment with web development, UI/UX, APIs, automation, and interactive interfaces.

> **A portfolio shouldn't only tell people what you can build.
> It should give them something to experience.**

---

## What is SPECTRE.OS?

SPECTRE.OS is an experimental developer portfolio built around a fictional operating system.

Instead of navigating through a conventional website, visitors interact with a desktop-like environment containing applications, windows, a terminal, project systems, and other interactive elements.

The entire interface is designed to feel like a personal developer workspace.

### 💻 Terminal

The terminal is one of the core parts of SPECTRE.OS.

It provides a command-line-inspired interface for interacting with and exploring the portfolio.

```text

        OS:           Spectre.OS
        Host:         Portfolio Desktop
        Kernel:       6.6.6-spectre
        Shell:        spectre-shell
        Theme:        Spectre Dark
        Status:       ONLINE

spectre@os:~$ _
```

The terminal isn't simply decorative. It is part of the overall interaction model and helps establish the identity of the operating system.

## 🔗 GitHub Integration

SPECTRE.OS can use GitHub as the source of truth for project information.

Repositories can be automatically indexed using GitHub metadata and topics.

For example, a repository can contain:

```text
spectre-portfolio
status-wip
```

to identify it as a portfolio project currently under development.

A completed project can use:

```text
spectre-portfolio
status-completed
```

Archived repositories can automatically be detected through GitHub's archived state.

This means adding a new project can be as simple as:

```text
CREATE REPOSITORY
       ↓
ADD spectre-portfolio
       ↓
SET PROJECT STATUS
       ↓
PUSH CODE
       ↓
SPECTRE.OS
       ↓
PROJECT INDEXED
```

The goal is to avoid manually editing the portfolio every time a new project is created.

## 🎨 Design Philosophy

SPECTRE.OS follows a simple design philosophy.

### 01 — The portfolio is part of the project

I wanted the portfolio itself to demonstrate the type of interfaces and systems I enjoy building.

### 02 — Interaction over scrolling

Instead of presenting everything as a long scrolling page, information is distributed throughout an interactive environment.

### 03 — Function over decoration

Visual effects are used to reinforce the operating-system concept rather than simply adding effects for the sake of appearance.

### 04 — Minimal futuristic aesthetic

The visual language is based around:

* Dark surfaces
* Monospace typography
* Technical display fonts
* Subtle glow
* Scanlines
* Glitch details
* Angular elements
* System indicators
* Minimal color accents

### 05 — Exploration

The interface is intentionally designed to encourage visitors to explore rather than simply read.

## 🧬 SPECTRE Identity

SPECTRE.OS uses a custom angular **S** symbol as its primary identity.

It appears across areas such as:

* Project system
